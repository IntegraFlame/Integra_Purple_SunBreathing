Summarized: the billed output count does not match the tokens you see. Progress updates are billed at full length in `usage.output_tokens`. This section gives **no $ rates** and **no separate `thinking_tokens` usage field**.
- **max_tokens:** includes all current-turn thinking. If input + `max_tokens` is larger than the window, the request is accepted (4.5+), and generation can end with `stop_reason: "model_context_window_exceeded"`. Max output is 128K on Opus 5.5 and Sonnet 5.5 (300K batches beta, `output-300k-2026-03-24`). The SDK **requires streaming when `max_tokens` > 21,333**. Use batch processing for more than about 32k thinking tokens per request.
- **Tools / interleaved:** with adaptive thinking, interleaving is automatic and needs no header. A tool loop is **one assistant turn** with a single thinking mode. Toggling mid-turn silently disables thinking. Thinking blocks must be passed back "complete and unmodified" within a tool turn (required). Passing them across turns is recommended. Opus 5.5 and Sonnet 5.5 **reject forced `tool_choice`** (`any`/`tool`); use `auto` with strict tools or structured outputs instead. You can't prefill while thinking is on. Progress-update blocks (Opus 5.5, Sonnet 5.5) are separate `thinking` blocks placed just before `tool_use`.
- **Signature/redacted:** `signature` is the encrypted full thinking. It is opaque, cross-platform, and identical whatever the `display` value. `redacted_thinking` has an opaque `data` field. Filtering only `type=="thinking"` "silently drops `redacted_thinking`" and breaks the protocol.
- **Preservation:** Opus 4.5+ and Sonnet 4.6+ keep all prior-turn thinking, which is billed as input. The prefix check means any change to `system`, `tools` or earlier messages invalidates later blocks; it is enforced by default for accounts created on or after 2026-08-31 00:00 UTC. Build append-only. Sonnet 5.5 blocks are account-bound. Opus 5.5 reads Sonnet 5.5 blocks; Sonnet 5.5 does **not** read Opus 5.5 blocks.
- **Caching:** changing thinking config or top-level effort starts the cache over. The doc suggests a 1-hour cache TTL for long thinking sessions.
- **Sampling:** a non-default `temperature`/`top_p`/`top_k` returns **400 on every request** on Opus 5.5 and Sonnet 5.5.
- **Streaming:** `thinking_delta` events, then one `signature_delta` before `content_block_stop`. Under `omitted` you get one empty `thinking_delta`. Use `stream.get_final_message()` instead of joining deltas yourself.

## 3 Contradictions with current wiring (verified in api_clients.py)
1. **Request shape OK:** `{"thinking":{"type":"adaptive"},"output_config":{"effort":...}}` (L152–155) matches the doc for 5.5. The doc confirms effort lives in `output_config` ("per-message `output_config` for effort changes"). It is redundant on 5.5, where adaptive is already the default.
2. **`enable_thinking=False` is a no-op (L146–147):** it returns `{}`, and on Opus/Sonnet 5.5 "no field" = adaptive thinking. Sending `"disabled"` would 400. The only real off switch is `between_tools` on Sonnet 5.5, at ≤`high` effort.
3. **Heimdall undercount/miscount (L187–188):** the code reads `usage.thinking_tokens`, a field this doc never mentions. Thinking is billed inside `output_tokens`. So `th_tok` is probably always 0. The `EMPTY_RESPONSE (N thinking tokens…)` message (L502) can't fire as intended. If the field ever existed, `tot_tok` would double-count. *(Whether SDK 1.5.0 has this field was not checked.)*
4. **Streaming path skips thinking kwargs (L543–552):** `generate_iterative` sends no `thinking`/`output_config`. It still thinks (adaptive default) but at whatever the API's default effort is. That differs from the non-stream path: cost differs and the cache splits. It also ignores `stop_reason`.
5. **No `stop_reason` handling:** a `max_tokens` stop gets lumped into a generic EMPTY_RESPONSE. `max_tokens=8192` (L437, L916) is far below the 128K ceiling.
6. **Model-detection heuristic (L149):** the tag `"-5-"` also matches dated 4.5 IDs (e.g. `claude-sonnet-4-5-2025…`). Those would get `adaptive`, which the doc says 400s on Sonnet/Opus/Haiku 4.5. That is latent, since 4.5 isn't routed now.
7. Grep found no `temperature`/`top_p`/`top_k`/`tool_choice` in api_clients.py, so it is compliant on those. Any future forced tool use on 5.5 will 400.
